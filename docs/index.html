下一步 · 審閱清單

採納不等於完成，負責人仍需人工確認。

    從輸入到交付，三步就看懂。

    原話、AI 解讀與你的決定，各自保留清楚的依據。

    01 ／ 放進會議

    貼上逐字稿，或匯入文字檔。

    支援 .txt／.md、最多 45,000 字元。先保留完整原文，再決定是否傳給 AI 整理。

    02 ／ 看見每個人

    看重點，也看不同的意見。

    用可改名、換頭像的人物卡區分發言。AI 整理與問答附原文引用，需要時能回到發言核對。

    03 ／ 帶走下一步

    審閱待辦，再寫入 Notion。

    由你確認內容、負責人與期限。預覽後才寫入，完成後還能從 Notion 讀回核對。

    不只是再產生一份摘要。

    真正難的，是會後要回找某個人的建議、釐清兩種意見，或確認一句「我會做」是否真的完成。記補住把這些問題放在人物與原文旁邊。

    由 AI 幫忙，由你做決定。

    頭像不等於身分驗證，承諾不等於完成，引用吻合也不保證解讀正確。重要工作保留人工審閱，才交到 Notion。

    目前為本機桌面版。多人即時共編與跨裝置同步尚未提供；會議工作階段請記得匯出備份。

    從真正的多人會議出發。

    人物、發言與工作分開呈現。需要時回到原話，不把頭像或模型解讀當作身分證明。

    實際瀏覽器紀錄：十人合成會議人物卡初版。後續版本已加入人物改名、換圖與卡片內問答；此截圖不當作後續功能的瀏覽器驗收證據。

    驗證了什麼，也說清楚界線。

    獨立交叉測試

    以 API handlers 與實際出貨頁面腳本驗證登入隔離、原文交接、取消、過期結果與人工審閱。這輪修正舊請求覆蓋新答案、儲存途中切換頭像的競態問題。

    真實 AI 與 Notion

    已有 17,255 字、十人合成會議的三分塊 DeepSeek 實測，以及 Notion 真實新增、獨立讀回與重送防重紀錄。人物問答三種題型已有真實回覆；一次引用校驗失敗與人工重試均保留紀錄。

    明確人工確認

    外傳全文前確認供應商；待辦採納、負責人、期限與 Notion 寫入分別審閱。AI 回報「完成」不會替你勾選完成。

    目前的產品範圍

    桌面本機版，具有本機帳號。多人即時共編、跨裝置會議同步、信箱驗證與忘記密碼尚未提供。自訂圖片的修後實機複驗未完成；不把自動測試代替真人使用驗收。

    把完整產品跑起來。

    需要 Node.js 24 或更新版本；AI 與 Notion 金鑰只放在你自己的服務端設定。

    git clone https://github.com/ccbibo/jibuzhu.git
cd jibuzhu
npm run start:background

    開啟 http://127.0.0.1:4173/welcome，先建立記補住帳號，再匯入會議。帳號與 Notion 帳號分開。

    規則整理可先使用。AI／Notion 實際串接需依 README 完成自己的服務端設定；GitHub 不含真實金鑰或個人會議資料。
